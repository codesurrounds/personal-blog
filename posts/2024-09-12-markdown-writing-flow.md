# 用 Markdown 重建我的写作流

我曾经在Word里写东西，光标总忍不住去调字号、改颜色。等反应过来，半小时过去了，正文一行没动。

## 为什么是纯文本

Markdown 是**为写作者设计的**，不是为排版者。你写 `# 标题`，它懂这是标题；你写 `- 列表`，它懂这是列表。格式退到幕后，思路才能走到台前。

## 我的最小工作流

1. 用任意纯文本编辑器开一个 `.md` 文件；
2. 只关心内容，括号里以后再加图；
3. 写完用渲染器预览，确认层级与代码块；
4. 发布到支持 Markdown 的平台。

代码块也能漂亮地高亮：

```bash
# 本地预览一个 md 文件
npx serve .
# 或者更轻量
python -m http.server 8000
```

## 工具对比

| 工具 | 优点 | 适合 |
| --- | --- | --- |
| Typora | 所见即所得 | 新手 |
| VS Code | 插件多 | 开发者 |
| 纸笔 | 零干扰 | 灵感期 |

> 工具永远只是工具。能让你**持续写下去**的那个，就是最好的。

这个博客本身，文章也是用 Markdown 写的——你正在读的这篇，就是它被渲染后的样子。
